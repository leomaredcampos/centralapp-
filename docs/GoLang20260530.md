## I. OTP Sending Implementation

### A. OTP Code Generator
**File:** `backend/utils/otp.go`

- Uses `crypto/rand` for cryptographically secure random generation
- Character set: `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#$%&*`
- Output: 6-character string
- Function: `GenerateOTP() string`

### B. Email Sender (SendGrid)
**File:** `backend/utils/email.go`

- **Service:** SendGrid (via `github.com/sendgrid/sendgrid-go`)
- **Function:** `SendOTPEmail(to, otp string) error`
- **Environment Variables:**
  - `SENDGRID_API_KEY` — SendGrid API key (required)
  - `EMAIL_USER` — sender email (optional, default: `noreply@yourdomain.com`)
- **Email Content:**
  - Subject: `"Your OTP Code"`
  - Plain text: `"Your OTP code is: <OTP>"`
  - HTML: `"<strong>Your OTP code is: <OTP></strong>"`
- **Error Handling:** Logs errors, returns error for status >= 400

### C. Login Flow (OTP Generation & Sending)
**File:** `backend/credential/login.go`

**HandleLogin (POST `/api/login`)**:
1. Decode JSON body with `email` field
2. Check email attempt lock (max 3 attempts per email)
3. Look up user in `userinfotbl` by `emailx`
4. If not found → record attempt, return `not_found` or `attempt_locked`
5. If TOTP enabled & verified → return `totp_required`
6. If `otpstatus = 'locked'` → return `locked`
7. Generate OTP via `utils.GenerateOTP()`
8. Store OTP in DB: `UPDATE userinfotbl SET otpkey=$1 WHERE emailx=$2`
9. Send OTP via email: `utils.SendOTPEmail(req.Email, otp)`
10. Log OTP sent, reset email attempts, set OTP sent timestamp
11. Return `{ status: "otp_sent", expires: <seconds_remaining> }`

**HandleVerifyOTP (POST `/api/verify-otp`)**:
1. Decode JSON body with `email` and `otp`
2. Check OTP attempt lock
3. Check OTP expiry (5-minute window via `attempts.go`)
4. Compare OTP from DB vs. request
5. If mismatch → record attempt, return `invalid_otp` or `attempt_locked`
6. On success → reset OTP attempts, set `otpstatus='locked'`, `otplogindate=NOW()`
7. Return `{ status: "verified" }`

### D. Rate Limiting & Attempt Tracking
**File:** `backend/credential/attempts.go`

| Parameter | Value |
|-----------|-------|
| Max attempts | 3 |
| Lock duration | 60 seconds |
| OTP expiry | 5 minutes |

**Storage Backend:** Dual-mode (Redis or in-memory fallback)
- Redis mode: Uses `redisconnection.RDB`, keys prefixed with `lock:` and `otp_sent:`
- In-memory mode: `map[string]*memRecord` with `sync.Mutex` protection

**Key Functions:**
- `isLocked(key string) (bool, int)` — checks if key is locked, returns remaining seconds
- `recordAttempt(key string) (bool, int)` — increments counter, locks at 3 attempts
- `resetAttempts(key string)` — clears lock for key
- `setOTPSentAt(email string)` — records OTP sent timestamp
- `isOTPExpired(email string) bool` — checks 5-min expiry
- `otpSecondsRemaining(email string) int` — returns remaining seconds

### E. TOTP (Two-Factor Authentication)
**Files:** `backend/utils/totp.go`, `backend/credential/totp.go`

**TOTP Generation:**
- Algorithm: HMAC-SHA1, 30-second period, 6-digit code
- Secret: 20 random bytes → Base32 encoded (no padding)
- URI format: `otpauth://totp/CentralApp:<email>?secret=<secret>&issuer=CentralApp&algorithm=SHA1&digits=6&period=30`
- Validation window: ±1 interval (3 checks: current, -1, +1)

**TOTP Endpoints:**
| Endpoint | Function | Description |
|----------|----------|-------------|
| POST `/api/setup-totp` | HandleSetupTOTP | Generate & return TOTP secret + URI |
| POST `/api/verify-totp-setup` | HandleVerifyTOTPSetup | Validate setup code, save secret to DB |
| POST `/api/verify-totp` | HandleVerifyTOTP | Verify TOTP code during login |
| POST `/api/check-totp-status` | HandleCheckTOTPStatus | Check if TOTP is enabled |
| POST `/api/disable-totp` | HandleDisableTOTP | Disable TOTP, clear sessions |
| POST `/api/check-totp-session` | HandleCheckTOTPSession | Check if TOTP session is active |
| POST `/api/delete-totp-session` | HandleDeleteTOTPSession | Delete a specific TOTP session |

**Login Flow with TOTP:**
1. HandleLogin → detects TOTP enabled → returns `totp_required`
2. HandleVerifyTOTP → validates code → creates session → returns sessionid
3. Dashboard checks sessionid in `localStorage`

## IV. Frontend Login Flow

**File:** `frontend/src/app/login/page.tsx`

**Step State Machine:** `"email"` → `"otp"` or `"totp"` → Dashboard

1. **EmailStep** → calls POST `/api/login` → receives:
   - `otp_sent` (with expires) → go to OtpStep
   - `totp_required` → go to AuthenticatorStep
   - `not_found` / `locked` / `attempt_locked` → stay on EmailStep
2. **OtpStep** → calls POST `/api/verify-otp` → on `verified`, stores email in localStorage → redirects to `/dashboard`
3. **AuthenticatorStep** → calls POST `/api/verify-totp` → on `verified`, stores email + sessionid + authtype in localStorage → redirects to `/dashboard`

### B. Strengths (Magaganda)

1. **Resilient Email Sending** — gumamit ka ng SendGrid, isa sa mga top email service providers. May proper error handling at logging.
2. **Redis Fallback** — kahit walang Redis server running, automatic na gumagamit ng in-memory storage para hindi masira ang login flow.
3. **3-layer Security** — Rate limiting (3 attempts) → OTP (temporary) → TOTP (authenticator app). Hindi beginner ang mag-isip ng ganito.
4. **Audit Trail** — lahat ng OTP sent, OTP verified, TOTP setup/disable, logout ay naka-log sa `centralizeaudit`.
5. **Session Expiry Checker** — may background goroutine na nagche-check ng expired sessions.

### C. Areas for Improvement

#### 1. Over-Engineered Layering (Simplify)

**Current (5 layers):**
```
main → finalcollector → finallayer → layerfolder → groupfolder
```

**Suggested:**
```
main → groupfolder (diretsahan)
```

Ang `finalcollector.go` at `finallayer.go` ay mga pass-through wrappers lang:
- `finalcollector.Start()` calls `finallayer.Start()`
- `finallayer.Start()` calls `layerfolder.Layer0001()`
- `layerfolder.Layer0001()` calls `groupfolder.Group0001()`

Walang ginagawang logic ang unang 3 layers — pwedeng tanggalin o i-merge.

#### 2. SQL Injection Risk sa App Access

**Current (save.go lines 128-133):**
```go
fmt.Sprintf(`INSERT INTO appaccess (..., %s) VALUES (...)`, appname)
```
Dynamic column name galing sa `selectedApps` — pwedeng i-inject ng attacker.

**Suggested Fix:** Magkaroon ng allowed app names whitelist:
```go
var allowedApps = map[string]bool{
    "app1": true,
    "app2": true,
}
if !allowedApps[appname] {
    continue
}
```

#### 3. OTP Character Set — Complicated para sa User

**Current:** `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#$%&*`

Ang OTP ay dapat madaling i-type ng user. Ang special characters (`!@#$%&*`) at mixed case ay pwedeng:
- Mag-cause ng typo error
- Mahirap i-type sa mobile
- Pwedeng magkaproblema sa URL/email encoding

**Suggested:** 6-digit numeric OTP (standard industry practice)
```go
const otpChars = "0123456789"
```

#### 4. Walang HTTP Middleware

Diretso `http.HandleFunc` — walang centralized:
- CORS middleware
- Request logging middleware (audit lang ang meron, hindi lahat ng request)
- Panic recovery (kung may runtime error, magca-crash ang buong app)
- Authentication middleware

**Suggested:** Gumawa ng simple middleware chain:
```go
func loggingMiddleware(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        log.Printf("%s %s from %s", r.Method, r.URL.Path, r.RemoteAddr)
        next(w, r)
    }
}
```

#### 5. Email Sending — Walang Template

**Current:** Hardcoded `<strong>Your OTP code is: <OTP></strong>`

**Suggested:** Gumamit ng HTML template para mas professional ang email:
```go
const otpTemplate = `
<!DOCTYPE html>
<html>
<body>
    <h2>CentralApp Verification</h2>
    <p>Your OTP code is: <strong>%s</strong></p>
    <p>This code expires in 5 minutes.</p>
</body>
</html>`
```

#### 6. Duplicate Upload Handler

Meron kang dalawang file upload functions:
- `appuserinfo/upload/upload.go` (naka-register)
- `userinfouserdata/userinfouserdata.go` (hindi naka-register, walang laman ang `RegisterRoutes()`)

Pwedeng pagsamahin o linisin.

### D. Solution mo sa Temporary Email (SendGrid) — Maganda

Ang ginamit mong **SendGrid** ay professional choice:

- ✅ **Reliable** — 99% uptime, hindi katulad ng self-hosted SMTP
- ✅ **Scalable** — kaya mag-handle ng maraming email
- ✅ **Free tier** — 100 emails/day free
- ✅ **Proper error handling** — may logging at error propagation
- ✅ **Environment variables** — hindi exposed ang API key

Kung gusto mo ng alternative na mas simple (walang third-party), pwedeng magdagdag ng **SMTP option**:
```go
func SendOTPEmailSMTP(to, otp string) error {
    auth := smtp.PlainAuth("", os.Getenv("SMTP_USER"), os.Getenv("SMTP_PASS"), os.Getenv("SMTP_HOST"))
    msg := []byte(fmt.Sprintf("Subject: Your OTP Code\r\n\r\nYour OTP code is: %s", otp))
    return smtp.SendMail(os.Getenv("SMTP_HOST")+":"+os.Getenv("SMTP_PORT"), auth, os.Getenv("SMTP_FROM"), []string{to}, msg)
}
```
