### Filing Rule (Backend)
- Every feature has its own folder and file
- `main.go` calls `RegisterRoutes()` per package — no route registration logic here
- Each package has its own `RegisterRoutes()` function — kapag nag-add ng bagong route, yung package file lang ang i-update, hindi si `main.go`
- Package name matches folder name
- Example: `backend/appuserinfo/rightbody/appuserinfoUSERDATA/` → `package appuserinfoUSERDATA`
- This mirrors the frontend folder structure so it's easy to find the corresponding backend for any frontend page

## 3. Design Philosophy

### Core Principle
> Clean, simple, corporate internal tool. Not flashy. Not pambata.

- No unnecessary animations or gradients
- White background throughout
- Subtle borders and shadows only
- Left-aligned content (not centered — centered is for portfolios, not enterprise tools)
- Consistent font: **Calibri 10.5pt** globally via `layout.tsx`

### Why Calibri 10.5pt?
- Standard corporate font (used in Microsoft Office, SAP, internal tools)
- 10.5pt is compact enough for dense forms but still readable
- Applied globally in `layout.tsx`:
```tsx
<body style={{ fontFamily: "Calibri, sans-serif", fontSize: "10.5pt" }}>
```

## 4. Login Page Design

### Structure
```
login/
├── page.tsx              ← Step controller
└── components/
    ├── EmailStep.tsx
    ├── OtpStep.tsx
    └── AuthenticatorStep.tsx
```

### Design Rules
- Centered card layout (login is the exception to left-align rule)
- White card with subtle shadow
- Logo at the top (`logo.png`)
- Input: full border, centered text, `9pt` font
- Label below the input (not above)
- Button: top and bottom border only, no left/right border
- `autoFocus` on every input
- Buttons disabled after click (`loading` state)

### Login Step Flow
```
Email submitted
    ↓
isLocked("email:{email}")? → attempt_locked + remaining seconds
    ↓
Email not found? → recordAttempt → not_found
    ↓
totp + totpverified='yes'? → totp_required → AuthenticatorStep
    ↓
otpstatus='locked'? → locked (account in use)
    ↓
Generate OTP → save to DB → send email → setOTPSentAt → otp_sent + expires → OtpStep

OTP submitted
    ↓
isLocked("otp:{email}")? → attempt_locked + remaining seconds
    ↓
isOTPExpired? → otp_expired → back to EmailStep
    ↓
OTP mismatch? → recordAttempt → invalid_otp
    ↓
Match → resetAttempts → otpstatus='locked' → verified → /dashboard

TOTP submitted
    ↓
isLocked("totp:{email}")? → attempt_locked + remaining seconds
    ↓
Invalid code? → recordAttempt → invalid
    ↓
Valid → resetAttempts → otpstatus='locked' → createTOTPSession → verified + sessionid → /dashboard
```

## 5. Login Attempt Tracking (In-Memory)

### File
`backend/login/attempts.go`

### How it works
- Uses Go `sync.Mutex` + `map[string]*attemptRecord` — no DB needed
- Key format: `"email:{email}"`, `"otp:{email}"`, `"totp:{email}"`
- 3 wrong attempts → locked for 60 seconds
- Auto-resets after lock duration expires
- Cleared on server restart (intentional)

### Constants
```go
maxAttempts  = 3
lockDuration = 60 * time.Second
otpExpiry    = 5 * time.Minute
```

### Functions
| Function | Purpose |
|---|---|
| `isLocked(key)` | Check if locked, returns remaining seconds |
| `recordAttempt(key)` | Increment count, lock if max reached |
| `resetAttempts(key)` | Clear on success |
| `setOTPSentAt(email)` | Record when OTP was sent |
| `isOTPExpired(email)` | Check if OTP expired (5 min) |
| `otpSecondsRemaining(email)` | Get remaining seconds |

## 9. 2FA Setup Page

### Flow
```
Click "Setup 2FA"
    ↓
/api/setup-totp → generate QR + secret → return to frontend (NOT saved to DB yet)
    ↓
User scans QR → enters 6-digit code
    ↓
/api/verify-totp-setup → validate code against secret
    ↓
Valid → save totp + totpverified='yes' to DB → 2FA enabled
Invalid → alert, try again

Click "Disable"
    ↓
/api/disable-totp → clear totp + totpverified + otpstatus + otpkey → deleteAllTOTPSessions
    ↓
All devices logout within 5 seconds
```

### Key Rule
- `totpverified = 'yes'` must exist for TOTP to be required on login
- If `totp` has value but `totpverified != 'yes'` → OTP flow used instead

## 10. TOTP Session Management

### Table
```sql
create table usertotp_sessions
(
id BIGSERIAL Primary Key,
emailx character varying(1000),
sessionid character varying(1000),
datemade timestamp
)
```

### Rules
- Max 3 active TOTP sessions per email
- Each session has unique `sessionid` (16-byte random hex)
- Stored in `localStorage` as `sessionid`
- `authtype = "totp"` stored in `localStorage`

### Functions
| Function | Purpose |
|---|---|
| `createTOTPSession(email)` | Check max 3, generate + save sessionid |
| `deleteAllTOTPSessions(email)` | Delete all sessions (on disable/setup change) |
| `HandleCheckTOTPSession` | Validate sessionid |
| `HandleDeleteTOTPSession` | Delete on logout |

## 11. Auto-Logout (5-Second Interval)

### dashboard/page.tsx
```tsx
setInterval(() => {
  if (authtype === "totp") → /api/check-totp-session
  else → /api/check-session

}, 5000)
```

- TOTP users: checks `usertotp_sessions` table
- OTP users: checks `otpstatus = 'locked'`
- Disable TOTP → all devices logout within 5 seconds

## 13. Database Queries

### Login — Check email + status
```sql
SELECT id, COALESCE(otpstatus,''), COALESCE(totp,''), COALESCE(totpverified,'')
FROM userinfotbl WHERE emailx = $1
```

### Login — Save OTP
```sql
UPDATE userinfotbl SET otpkey = $1 WHERE emailx = $2
```

### Login — Verify OTP
```sql
SELECT otpkey FROM userinfotbl WHERE emailx = $1
```
- Use `strings.TrimSpace()` on both sides before comparing

### Login — Lock session
```sql
UPDATE userinfotbl SET otpstatus = 'locked' WHERE emailx = $1
```

### Logout — Clear OTP session
```sql
UPDATE userinfotbl SET otpstatus = '', otpkey = '' WHERE emailx = $1
```

### Session Check
```sql
SELECT COALESCE(otpstatus,'') FROM userinfotbl WHERE emailx = $1
```

### Get Accessible Apps
```go
// Step 1
SELECT appname, buttonname FROM apptbl WHERE appstatus != 'deactivated'
// Step 2 — dynamic column check
SELECT COALESCE(TRIM(appname_column),'') FROM appaccess
WHERE emailx = $1 AND writemade != 'deleted' LIMIT 1
```

### Get Available Apps (Module Access dropdown)
```sql
SELECT appname, buttonname FROM apptbl WHERE COALESCE(writemade,'') != 'deleted'
```

### Save User Info
```sql
INSERT INTO userinfotbl (..., writeremail, writemade, datemade)
VALUES (..., $writeremail, 'Inserted', NOW())
```

### Save App Access
```go
// Dynamic column — column name = appname
INSERT INTO appaccess (emailx, writeremail, writemade, datemade, appname_column)
VALUES ($1, $2, 'Inserted', $3, 'Yes')
```

### List Users (Search combo)
```sql
SELECT emailx, fname, lname FROM userinfotbl
WHERE COALESCE(writemade,'') != 'deleted' ORDER BY lname, fname
```

## 17. 1-Day Session Expiry

### File
`backend/credential/session_expiry.go`

### How it works
- Goroutine runs every 1 minute checking for expired sessions
- Started via `StartSessionExpiryChecker()` called in `credential.RegisterRoutes()`

### OTP Expiry
```sql
UPDATE userinfotbl
SET otpstatus='', otpkey=''
WHERE otpstatus='locked'
AND otplogindate IS NOT NULL
AND otplogindate < NOW() - INTERVAL '1 day'
```
- `otplogindate` saved when OTP is verified
- After 1 day → `otpstatus=''` → 5-second check detects invalid → auto logout → can login again

### TOTP Expiry
```sql
DELETE FROM usertotp_sessions
WHERE datemade < NOW() - INTERVAL '1 day'
```
- After 1 day → session deleted → 5-second check detects invalid → auto logout → count back to 0 → can login again on 3 devices

### New DB Column
| Column | Table | Purpose |
|---|---|---|
| `otplogindate` | `userinfotbl` | Timestamp of last OTP login — used for 1-day expiry |
